# Шифрование переписки

Текст сообщений и данные уведомлений хранятся с Laravel `encrypted` casts.
Вложения шифруются через `Crypt::encryptString` перед постоянным сохранением;
скачивание проверяет доступ к чату, проверяет целостность и возвращает исходные
байты без сохранения расшифрованной копии на диск. Пересылка сохраняет признак
шифрования общего файла. Используются AES-256-CBC и MAC, настроенные в Laravel.

Это серверное шифрование: приложение с ключом может читать данные.
Имена файлов, размеры, MIME-типы, участники, названия чатов и даты не шифруются.
HTTPS/WSS по-прежнему необходимы. Временные загрузки Livewire до отправки
сообщения остаются обычными файлами: для их защиты требуется шифрование диска
и штатная очистка временных загрузок. Старые бэкапы и свободные страницы БД
могут содержать открытый текст; данный переход не выполняет безопасное стирание
носителя и не изменяет ранее созданные резервные копии.

## Переход существующей установки

Перед переключением кода остановить запись: закрыть доступ к чату через
`php artisan down`, остановить фоновые процессы, которые обращаются к переписке.
Сделать согласованную резервную копию БД и `storage/app/private`. Сохранить
текущий `APP_KEY` в отдельном защищённом хранилище; не включать его в копию БД.
Не запускать `key:generate` для существующей установки.

С новым кодом и прежним ключом выполнить:

```bash
php artisan migrate --force
php artisan chat:encrypt-attachments
```

Миграция шифрует все существующие сообщения, включая удалённые через soft delete,
и данные уведомлений в транзакции. Колонки расширяются до LONGTEXT для шифротекста.
Команда файлов создаёт зашифрованный файл по новому пути, обновляет все ссылки
на общий файл в транзакции и затем удаляет открытый оригинал. Журнал очистки
позволяет закончить удаление после прерывания процесса. При ошибке нужно устранить
причину и повторить команду; уже зашифрованные вложения повторно не шифруются.
Отсутствующий исходный файл команда отмечает ошибкой, не изменяя ссылки на него.
Запускать команду в одном экземпляре при остановленной записи в чат.

После успешного завершения проверить чтение сообщений и скачивание вложений,
перезапустить фоновые процессы с новым кодом и выполнить `php artisan up`.
Новые сообщения, уведомления и постоянные вложения шифруются автоматически.
До завершения команды старые файлы остаются читаемыми через прежний механизм.

Автоматический rollback шифрования текста запрещён: для отката восстановить
согласованный бэкап БД и файлов вместе с прежним кодом и прежним ключом.

## Ключи

Потеря `APP_KEY` лишает доступа к данным. Все экземпляры приложения и очереди
должны использовать одинаковый ключ. Для ротации Laravel поддерживает
`APP_PREVIOUS_KEYS`; старые ключи нельзя удалять, пока соответствующие сообщения,
уведомления, файлы и резервные копии ещё нужны. Сама смена ключа не перешифровывает
существующие данные.

Документация: https://laravel.com/docs/13.x/encryption
